01 · 為什麼需要翻譯官

01外交官遇上台灣人

電腦的 USB 孔講的是一套嚴謹的協定：資料被包成一個個封包，用差動訊號送出，像美國外交官的正式英文。單晶片（MCU）的 TX／RX 腳講的是 UART：一個位元組、一個位元慢慢送，像台灣人習慣的口語中文。兩邊直接相接只會各說各話，所以中間要有一位口譯員，也就是 CH340C 這種橋接器。

02 · 認識口譯員

02CH340C 長什麼樣子

CH340C 是沁恒（WCH）的 USB 轉 UART 晶片。USB 那一側只要 UD+、UD− 兩條線接到電腦；UART 那一側用 TXD、RXD 傳資料，另外有 VCC 和 GND 供電。它內建振盪器，不必外接石英，電壓可以是 3.3V 或 5V。點一下晶片上的腳位，看每一腳負責什麼。

點一個彩色腳位，這裡會說明它的工作。

示意圖只標功能名稱，實際腳位編號與電壓接法請以 WCH 官方資料表為準。

03 · 英文翻成中文

03電腦 → 單晶片

電腦把要送的資料放進 USB 封包。CH340C 先用 CRC 檢查碼確認沒有錯，再取出裡面的位元組，改用 UART 的說法一次送一個：先拉低一個 Start 位元，接著 8 個資料位元（LSB 先送），最後拉高 Stop 位元收尾。這種格式常寫成 8N1。選一個字元，拖動滑桿看它在 TXD 上怎麼一格一格送出。

04 · 中文翻成英文

04單晶片 → 電腦

反方向剛好相反。單晶片從 TX 一個字一個字說話，CH340C 先把它們收進緩衝區暫存。USB 的規則是主機問了裝置才能答，所以資料要等電腦送來一個 IN 詢問（輪詢）才會被打包送回去。緩衝區是空的時候，CH340C 回 NAK，意思是「還沒有，等一下再問」。

05 · 說話的速度

05語速不同，就變亂碼

UART 沒有時脈線，雙方只能事先約好說話的速度，這個速度叫鮑率，單位是 bps。接收端偵測到 Start 位元的下降緣後，照自己的鮑率在每一位元的正中間取樣。兩邊差太多，取樣點會慢慢滑到錯的位元上，結果就是亂碼。調調看下面的設定。

06 · 接線小實驗

06TX／RX 接線小實驗

接線有三個重點。第一，說話的嘴要對著對方的耳朵：CH340C 的 TXD 接單晶片的 RX，RXD 接 TX。第二，兩邊要共地，訊號才有同一個參考點。第三，電壓準位要相符：單晶片的 UART 腳常用 TTL 準位，3.3V 的單晶片別直接吃 5V 的訊號。先點一個左邊腳位，再點一個右邊腳位來接線；再點一次已接的線可以拆掉。

CH340C 電壓
單晶片電壓
邏輯準位：Vcc = 5V 時，多少伏算 0、多少伏算 1？
實線＝VIL，低於它判為低電位虛線＝VIH，高於它判為高電位
線上的電壓

重點：CH340C 在 5V 時輸入門檻是 VIH ≥ 2.3V，所以 3.3V 單晶片的 TX 可以直接接 CH340C 的 RXD。危險的是反方向：CH340C 的 TXD 輸出約 5V（VOH ≥ 4.4V），直接接 3.3V 單晶片的 RX 可能損壞它。ATmega328P 這類單晶片的輸入門檻與標準 TTL 不同，請看各自資料手冊。
07 · 自動重置燒錄

07DTR# 如何讓 Arduino 自動重置

Arduino（ATmega328P）的 PC6（第 1 腳）就是 RESET#，重置腳，低電位有效。它用一顆 10 kΩ 上拉電阻接 5V 保持高電位，同時經一顆 0.1 µF 電容接到 CH340C 的 DTR#。電腦開啟序列埠時 DTR# 被拉低，電容把這個下降的瞬間傳給 RESET#，形成一個負脈衝，MCU 因此重置並進入 bootloader 等待上傳程式，這就是自動重置燒錄。

RESET# 腳的電壓長什麼樣子（示意）
電容 C
上拉電阻 R
DTR#RESET#色塊＝上方目前步驟對應的時間範圍

虛線畫在 0.2 VCC（5V 供電時 1.0V）：RESET# 低於它就視為低電位。依 Microchip 資料手冊（ATmega328PB 的 Table 33-6），RESET 腳門檻 VRST 最小 0.2 VCC、最大 0.9 VCC，這裡採用最嚴格的下限 0.2 VCC：只要低於它，無論門檻落在範圍內哪裡都一定算低電位，算出來的低電位時間是保守的（最短的）。tRST（RESET 腳最短脈衝寬度）為 2.5 µs，低電位的時間要比它長才能保證產生重置。以上數值僅供參考，圖也忽略了 MCU 內部保護二極體與寄生電容。

08 · 口譯員報到

08電腦怎麼認得它

接好線之後，電腦還得先認識這位口譯員。插上 USB 後，電腦會做列舉，讀出它的身分（VID:PID）；接著載入對應的驅動程式，才會多出一個 COM 埠給應用程式用。這個 COM 埠是驅動模擬出來的虛擬序列埠，USB 那一側仍然是 USB。
